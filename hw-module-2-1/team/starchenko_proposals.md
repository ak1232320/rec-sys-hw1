## 2. Разделение треков: ты делаешь добивку, я переставляю повторы

Список `latest_buy` состоит из двух частей: префикс (прошлые активы клиента, последние сверху) и добивка популярным. Твой вопрос (Encoder) меняет добивку. Мой вопрос (Ranker) меняет порядок внутри префикса, добивка у меня остаётся как в `latest_buy`. Эти два изменения не пересекаются. На клиентах, которые в окне покупают только то, что уже брали, добивка ничего не меняет, это твой же инвариант. Поэтому проектная схема «baseline, encoder-only, ranker-only, оба вместе» получается с чистой абляцией без лишней работы.

Мой вопрос для Session 1: улучшает ли переранжирование LLM прошлых активов клиента (те же датированные Buy и Sell, те же метаданные as-of) nDCG@10 по сравнению с логистической регрессией на той же информации, для тёплых клиентов и отдельно для клиентов с более чем 10 прошлыми активами.

## 3. Цифры пилота (9 квартальных срезов 2020-09-01 … 2022-09-01, горизонт 30 дней, тёплая когорта)

Моя независимая реализация воспроизводит твои числа: 12 163 размеченных окна, 5 051 с новым для клиента активом, `latest_buy` 0.561 по размеченным (макросреднее по срезам). На демо-срезе 2021-06-01 мои списки `latest_buy` совпадают со стартером у всех 100 пользователей.

| Вариант (nDCG@10, размеченные, макросреднее по 9 срезам) | Значение |
|---|---:|
| `latest_buy` | 0.561 |
| префикс по частоте покупок | 0.530 |
| префикс по логистической регрессии (обучена на срезах до 2020-09-01) | 0.566 |
| добивка по совместным покупкам (item-item) | 0.569 |
| оракул категории для добивки (потолок) | 0.580 |
| оракул добивки (потолок, как у тебя) | 0.639 |
| оракул порядка префикса (потолок) | 0.750 |

- 7 112 из 12 163 размеченных окон (58%) содержат только повторные покупки. Добивка на них не влияет, а `latest_buy` там даёт 0.760.
- У 3 688 окон больше 10 прошлых активов. Там `latest_buy` даёт 0.495, потолок перестановки 0.818, логистическая регрессия 0.508.
- Отрицательный результат: переключатель «повтор или новое», который ставит первые m популярных новых активов перед префиксом, хуже `latest_buy` даже как оракул (0.557 при m=1). Позиция нового без хорошего выбора нового ничего не даёт. Этот вариант я снимаю.
