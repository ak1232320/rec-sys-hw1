# Ручная проверка для отчёта Session 2 (делает Алексей, не Claude)

Задание требует лично проверить хотя бы один важный результат и описать, как именно.
Ниже три проверки по 5–10 минут. Сделайте хотя бы первую, скриншоты кладите в эту
папку (`manual/`), а мне напишите, что подтвердилось. До этого раздел
«What I personally verified» в отчёте остаётся жёлтым TODO.

## 1. Один клиент: ID в списке и nDCG@10 вручную (главная проверка)

Клиент с префиксом ID `6B1591…` (тот же, что в примере данных Session 1).

1. `outputs/demo/predictions.csv`: отфильтровать `user_id` по началу `6B1591`,
   `method = llm_fill`. Ожидается: ранги 1–2 = `GRC4261213D5`, `GRF000036001`
   (его прошлые покупки, префикс), ранг 3 = `GRF000045002`.
2. `../hw-module-2-1/data_raw/FAR-Trans/transactions.csv`: строки этого клиента.
   Проверить, что до 2021-06-01 у него есть покупки (`Buy`) `GRF000036001` (2020-02-14)
   и `GRC4261213D5` (2021-03-19), а `GRF000045002` он купил 2021-06-02, внутри окна
   2021-06-01 … 2021-06-30. Строка 2018-01-02 `GRS434003000` с отрицательным
   `transactionID` — реконструированная начальная позиция: стартер исключает такие строки
   по умолчанию, поэтому в историю она не входит.
3. Посчитать nDCG@10 руками: одна релевантная позиция на ранге 3, idealDCG = 1/log2(2) = 1,
   DCG = 1/log2(3+1) = 0.5, значит nDCG = 0.5. Сравнить с `outputs/demo/per_user.csv`
   (строка `llm_fill` этого клиента: 0.5). Для `latest_buy` того же клиента должно быть 0:
   `GRF000045002` нет в его десятке.
4. Сверить с таблицей: 0.5 / 11 размеченных клиентов ≈ +0.0455 к среднему по непустым.

## 2. На вход модели не попадают будущее и клиенты

1. Открыть `kaggle/input/asset_texts.json`: там только тексты вида
   «название | категория | подкатегория | сектор | отрасль | рынок» и их sha256.
   В них нет ни дат, ни ID клиентов, ни сумм.
2. Открыть ноутбук на Kaggle (`alekseykosychev/far-trans-asset-embeddings`, приватный)
   и убедиться, что он читает только эти тексты и пишет `.npy` и `manifest.json`.
3. По желанию: запустить `python -m unittest discover -s tests -v`. Тест
   `test_predictions_are_blind_to_rows_at_or_after_the_cutoff` удаляет все строки
   с датой ≥ 2021-06-01 из всех четырёх CSV и проверяет, что ни один список не изменился.
