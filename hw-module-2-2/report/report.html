Abstract

In Session 1 I asked whether frozen LLM text embeddings of as-of asset metadata, used only to fill the Top-10 slots that the recency prefix of the provided latest_buy baseline leaves empty, improve nDCG@10 over a popularity, categorical or TF-IDF fill. I implemented this Encoder-track change with the open-weight Qwen/Qwen3-Embedding-0.6B (pinned revision, run on a Kaggle T4) and compared it with the four provided baselines and matched controls. On the HW2 protocol (100 warm users, cutoff 2021-06-01, 30 days) the LLM fill scores highest: nDCG@10 0.0294 over all users and 0.2672 over the 11 users with purchases, but the whole margin comes from one customer. On nine quarterly development cutoffs (12,163 labelled user-windows) it is the worst fill for users who buy an asset new to them: 0.2256 vs 0.2813 for popularity (paired difference -0.0624), lower on all 9 cutoffs. It fills slots with rarely bought assets. The result is negative, and it is reported as such.

Index Terms — financial asset recommendation, LLM text embeddings, content-based filtering, nDCG, FAR-Trans

1. Introduction

Problem and question. Each evaluated FAR-Trans customer gets a Top-10 asset list, scored by nDCG@10 against the purchases in the next 30 days under a past-only protocol [1], [3]. The strongest classical baseline, latest_buy, is two parts: a prefix (the customer's own past buys, most recent first) and a fill (the most popular other assets). Customers hold few distinct assets, so most of every list is fill. Fill is also the only part that can reach an asset new to the customer. Session 1 fixed the question (Encoder track):

We test whether frozen LLM text embeddings of the as-of asset description (intervention) improve nDCG@10 against purchases in the next 30 days (outcome) over the same pipeline whose fill uses popularity, the starter's categorical tokens or TF-IDF (control) for warm FAR-Trans customers, overall and on those whose label window holds an asset new to them (population).

What changed since Session 1. The LLM arm was planned then; it is now implemented and run. Session 1 named multilingual-e5-base as the candidate. That model is an XLM-RoBERTa encoder, not an LLM, so the primary model is now an LLM-based embedder, Qwen3-Embedding-0.6B [6]. The e5 model stays as a control and answers one question: is the effect due to the LLM, or to any dense encoder?

Place in the pipeline. history → latest_buy prefix (unchanged) → fill candidates = eligible assets not in the prefix → score = cosine between the asset vector and the buy-count-weighted history profile → Top-10 → the starter's nDCG@10. Only the vector space differs between arms.

3. Method

Arms. All arms keep the latest_buy prefix (its first min(10, |history|) items) and differ only in the fill. pop_fill is popularity and reproduces latest_buy exactly (0 of 100 demo users and 0 of 102,321 development user-windows differ). tokens_fill uses cosine in the starter's categorical token space. tfidf_fill uses cosine over unigram TF-IDF of the asset text. e5_fill and llm_fill (mine) use cosine over the mE5-base and Qwen3-Embedding vectors of the same text. *_top20 re-orders the 20 most popular unseen assets by the space's cosine. oracle_fill places the user's new-to-user label assets (a ceiling, not a method). Ties break by popularity rank, then ISIN. Scores are rounded to 10⁻¹² before tie-breaking: without this, float sums over Python sets followed the per-process hash seed and flipped ties between runs (found while reproducing the Session 1 pilot).

Model input and inference. The text is name | category | subcategory | sector | industry | market from the latest asset row strictly before the cutoff, with empty fields omitted, e.g. DHLOS SYNTHESIS BEST FUND OF FUNDS ΜΕΤΟΧΙΚΟ | MTF | Money Market | AEDAK. The texts carry no user, date or transaction field. The 736 unique texts of the nine cutoffs are embedded once. Embedding is per text, so a text of a later cutoff cannot change an earlier vector, and each cutoff looks up only its own as-of texts. Qwen/Qwen3-Embedding-0.6B at revision 97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3 (Apache-2.0, 595,776,512 parameters): float32, last-token pooling, L2-normalised, 1,024 dimensions. Asset texts are encoded as documents without an instruction (the repository's document prompt is empty). Batch size is 32 and the longest input is 60 tokens (none truncated). intfloat/multilingual-e5-base at 835193815a3936a24a0ee7dc9e3d48c1fbb19c55 uses the "query: " prefix that its card advises for symmetric similarity, with mean pooling. Inference ran on Kaggle (Tesla T4, CUDA 13.0, Python 3.13.16, torch 2.11.0+cu130, transformers 5.20.2, sentence-transformers 5.7.0). A second encoding pass was bit-identical (max |Δ| = 0.0). Scoring and evaluation run locally on CPU (i5-13420H, Python 3.14, numpy 2.4). Code: kaggle/embed_assets.py, src/fill.py.

Fair comparison and failure handling. Users, cutoff, eligibility, labels and nDCG@10 come from the unchanged starter, imported as a module. My run's protocol_hash equals that of a separate starter CLI run, and all 4,000 baseline prediction rows are byte-identical. The fill candidates are all eligible assets not in the prefix; the starter's 50-candidate CBF list is not used. Nothing is generated, so there is no parsing failure. A missing, misaligned (sha256 per text) or non-finite vector aborts the run. A user with an empty profile would get the popularity fill and count as a failed case; none occurred. Leakage test: deleting every CSV row dated on or after the cutoff leaves all lists unchanged. The development protocol (nine quarterly cutoffs 2020-09-01 … 2022-09-01, all warm users, never filtered by future purchases) was fixed in Session 1, before the LLM arm existed.

Who moves. Of the 11 users with purchases, 5 bought only assets they held before. The fill cannot change their score: all fill arms tie, as the tests check. Three more bought a new asset but have ten or more past assets, so no slot is free. Of the remaining three, one customer (6B15…, the data example of Session 1) is rescued. He held a "DHLOS SYNTHESIS BEST YELLOW" fund and buys the sibling "DHLOS SYNTHESIS BEST FUND OF FUNDS". Both dense spaces put it at rank 3 (nDCG 0.5). TF-IDF reaches only rank 8, because his oil-refinery bond pulls the fill towards Petrobras and Pemex bonds. One customer is lost: his purchase sat in the popularity fill at rank 7. One is missed by every arm. The +0.0017 all-user margin of llm_fill over latest_buy is therefore the net of one rescue and one loss. On the 100-user samples of the other development cutoffs the LLM fill is below the popularity fill in 5 of 9 and above it in 3.

The confidence intervals come from a percentile bootstrap over pooled with-new user-windows. A customer seen at several cutoffs is not clustered, so the intervals are optimistic.

Findings. (i) On the with-new users the LLM fill is the lowest of all fills: below popularity on 9/9 cutoffs, below TF-IDF on 9/9 and below mE5 on 9/9. It places 386 new-to-user purchases in the Top-10, against 1,472 for popularity. (ii) The non-LLM mE5 encoder is the best content space, but it still loses to popularity (above it on 2 cutoffs). (iii) Restricting the LLM order to the 20 most popular unseen assets recovers most of the loss (llm_top20), and TF-IDF inside the same prior roughly ties popularity. The prior, not the semantic order, carries the score. (iv) An oracle fill reaches 0.4697 on with-new users, so the headroom is real.

Failure analysis (cutoff 2021-06-01; outputs/dev/diagnose_2021-06-01.json). New-to-user purchases are 88% stocks with a mean popularity rank of 44. The mean popularity rank of the filled assets is 4 for popularity, 53 for tokens, 102 for mE5, 193 for TF-IDF and 204 for the LLM. The Qwen3 space is far less compressed: its mean pairwise cosine is 0.48, against 0.81 for mE5. Its nearest neighbours are name-and-issuer siblings, and most of them are long-tail assets that almost nobody buys. Semantic closeness is not purchase propensity in this data.

Checks run by code (AI-performed, tests/test_fill.py and the run outputs). The starter's 58 tests pass on the unchanged copy. My 19 tests pass: fill units, embedding alignment and finiteness, pop_fill = latest_buy, the repeat-only tie, prefix preservation, the protocol and baseline match with a fresh starter run, the future-blind test, and hash-seed independence. The non-LLM arms match the Session 1 pilot up to tie-breaking (max |Δ| = 0.0006).

5. Discussion

What improved, what failed. The implementation works end to end: a pinned open-weight LLM, reproducible vectors and a fair, cross-checked comparison. The question has a clear answer on the development data: LLM embeddings of terse asset metadata are the worst fill, worse than sparse features and worse than a smaller non-LLM encoder. The positive 100-user number is a single-user event; I report it and do not claim it. For the product-owner decision framed in Session 1, this argues against LLM-embedding infrastructure for the fill as it stands.

Next controlled experiment. Changes: one term, the fill score becomes cosine + λ·log(1 + buyers). λ is chosen on the 2020-09 … 2021-03 cutoffs and tested on the six later ones. Fixed: prefix, users, cutoffs, texts, model, revision and vectors. A second, model-side variant (Qwen3 with the same retrieval instruction on both sides) waits until the first one is settled.

Threats to validity. One model and one input template. The asymmetric Qwen3 model is used symmetrically, as documents. The bootstrap ignores repeated customers. 93% of new-to-user labels are stocks. The data cover one institution, 2020–2022. The HW2 sample has 11 labelled users, so its ordering of methods is not evidence. No suitability, return or profit claim is made.
