# Session 2 (Starchenko): zero-shot LLM reranking of a customer's own past assets

Ranker track. Every arm keeps the `latest_buy` structure (own past assets first, then the
popularity fill of never-bought assets) and changes only the order of the past assets:

| Arm | Prefix order | Code |
|---|---|---|
| recency (= `latest_buy`) | most recent Buy first | `PREFIX_ARM=recency` |
| LR control | logistic regression on as-of features, trained on 2019-03 ... 2020-06 windows | `lr_control.py`, `PREFIX_ARM=lr` |
| input-order control | the order in which the prompt lists the assets (by ISIN), no model | `PREFIX_ARM=input_order` |
| LLM (mine) | Qwen/Qwen3-1.7B, zero-shot, greedy, thinking off | `server/run_prefix_llm.py`, `PREFIX_ARM=llm` |

`starter/` below is an unchanged copy of the course starter
(`dryjins/RecSys-LLMs/project/far-trans`); it is not committed here.

Protocol: the starter's defaults (100 warm users, cutoff 2021-06-01, 30-day window, repeats
allowed), except `--candidate-count 767` (all eligible assets), because the popularity fill
is not inside the default 50 CBF candidates. The four provided baselines are unchanged by
this flag; `protocol.json` differs from the default run only in `candidate_count`.

## Reproduce

```bash
DATA=/path/to/FAR-Trans   # folder with transactions.csv etc.
# 1. four baselines with starter defaults
python starter/starter.py run --data-dir $DATA --output-dir outputs/baseline
# 2. past-only inputs: latest_buy prefix and fill, prompts for users with >= 2 past assets
python experiments/build_inputs.py starter $DATA outputs/baseline outputs/inputs
# 3. matched classical control
python experiments/lr_control.py starter $DATA outputs/inputs
# 4. LLM generation on a GPU (vLLM 0.19.1, torch 2.10.0+cu128, transformers 5.20.2)
python server/dl_qwen17.py            # Qwen/Qwen3-1.7B @ 70d244cc86ccca08cf5af4e1e306ecf908b1ad5e
python server/run_prefix_llm.py outputs/inputs/prompts.jsonl out   # -> raw_outputs.jsonl, run_meta.json
cp out/raw_outputs.jsonl outputs/inputs/
# 5. each arm through the unchanged starter
for ARM in recency lr input_order llm; do
  PREFIX_ARM=$ARM PREFIX_DIR=outputs/inputs python starter/starter.py run --data-dir $DATA \
    --output-dir outputs/change_$ARM --plugin experiments/prefix_plugin.py --candidate-count 767
done
python experiments/analyze.py outputs
```

`pilot_gate.py` and `pilot_prefix_lr.py` are the Session 1 pilot code, reused unchanged for
training the LR control. `truncate_future.py` is the leakage test: prompts built from CSVs
without any row dated on or after the cutoff are byte-identical to the real ones.
No user-level outputs are committed (prompts and raw model outputs are regenerated by the
scripts); aggregate metrics, protocol hashes and run metadata are in `results/`.
